PURPOSE
Maintain an auditable, patch-driven workflow to align the OpenCode harness,
technical documentation, statistical metrics, Javadocs, and thesis chapters
with the refactored compiler.* architecture. Every change is proposed as an
independent unified diff patch; applying and committing remain strictly under
user control. See handoff/PATCH_PROTOCOL.md for the mandatory patch contract.

CURRENT ARCHITECTURE BASELINE (PRODUCTION & TEST)
- compiler.FlcCompiler: end-to-end orchestration facade (not a sixth phase).
- compiler.lexer: lexical analysis (JFlex + preprocessors + semantic analyzers).
- compiler.parser: syntactic and semantic analysis (Bison + initializations).
- compiler.ast: abstract syntax tree nodes and visitors.
- compiler.generator: controller model and C++ code generation, including
  compiler.generator.lowers (AST-to-ControllerModel lowering).
- compiler.repository: SymbolTable, LexemeInfo, and DiagnosticsHandler.
- src/test/java/utils/simulation: testing infrastructure comparing
  ReferenceSimulator and QuantizedSimulator (not a production module).

HARNESS POLICY RULES
- Agents in opencode.json MUST keep write=false and edit=false.
- Agents NEVER edit tracked source, documentation, or thesis files directly.
- Agents deliver proposed changes exclusively as unified diff patches with
  explicit metadata (ID, Objective, Motivation, Scope, Changes, Risks,
  Validation, Dependencies).
- Do NOT append to /.opencode/log.txt (deprecated non-existent path).
- Applying a patch (git apply) and creating a commit (git commit) are two
  separate human decisions.

DOCUMENTATION & SIMULATION INVARIANTS
Documentation must match the current implementation. A Javadoc comment that
names an old package, claims immutability where fields are mutable, or describes
a former pipeline is worse than no comment. Avoid blanket statements such as
"all public methods documented" until an audit verifies that claim.

The current test harness compares ReferenceSimulator and QuantizedSimulator
over a finite input grid. step=1 enumerates the model's representable input
combinations; larger steps sample. It covers MIN-MAX and centroid of
singletons only. It does not execute generated C++, synthesize hardware, prove
formal equivalence, or establish full IEC 61131-7 compliance.
