# utils

Shared compiler state and semantic metadata: symbol table, `LexemeInfo` DTO, diagnostics, builders, and classification enums.

Last update: 2026-10-30

## Purpose

The `utils` package is the shared repository for every compiler phase. It contains the symbol table that stores semantic metadata, the `LexemeInfo` DTO that carries that metadata, the diagnostics collector and diagnostic hierarchy, the builder API used to construct `LexemeInfo`, and the enums that classify symbols.

The package is consumed by the lexer, the parser, the parser publishers and facades, the lowering phase, and the compiler entry point. `utils` itself has no outgoing dependency on another compiler package: it only depends on the JDK, the SpotBugs annotations, and its own `utils.enums` and `utils.diagnostics` subpackages. This page documents `utils` and its subpackages `utils.builders`, `utils.enums`, and `utils.diagnostics`. Helper classes in `parser.utils`, `lexer.semantics.utils`, and `lexer.transformers.utils` belong to the parser and lexer module pages.

Source files:

* `src/main/java/utils/SymbolTable.java`
* `src/main/java/utils/LexemeInfo.java`
* `src/main/java/utils/DiagnosticsHandler.java`
* `src/main/java/utils/builders/*.java`
* `src/main/java/utils/enums/*.java`
* `src/main/java/utils/diagnostics/*.java`

## Builder Recipes

`utils.builders.Director` is a non-instantiable utility class. Its static methods configure a `LexemeInfoMutator` and, for literal recipes, return the source spelling of the literal.

| Method                    | Configuration                                            | Return value |
|---------------------------|----------------------------------------------------------|--------------|
| `makeWithMetadata`        | Copies every `LexemeInfoView` attribute into the mutator | `void`       |
| `makeLiteral`             | `type=SIMPLE`, `use=LITERAL`, `source=NONE`              | `void`       |
| `makeIntegerZeroConstant` | Literal recipe plus `subtype=INT`, `initialValue=0`      | `"0"`        |
| `makeDefaultInteger`      | Delegates to `makeIntegerZeroConstant`                   | `"0"`        |
| `makeDefaultReal`         | Literal recipe plus `subtype=REAL`, `initialValue=0D`    | `"0.0"`      |
| `makeDefaultBoolean`      | Literal recipe plus `subtype=BOOL`, `initialValue=false` | `"FALSE"`    |
| `makeTrueBoolean`         | Literal recipe plus `subtype=BOOL`, `initialValue=true`  | `"TRUE"`     |
| `makeDefaultString`       | Literal recipe plus `subtype=STRING`, `initialValue=""`  | `''`         |
| `makeDefaultWString`      | Literal recipe plus `subtype=WSTRING`, `initialValue=""` | `""`         |

## How to test

Primary unit test: `src/test/java/unit/utils/SymbolTableTest.java`, tagged with `@Tag("utils")`.

| Test method                                      | Verifies                                                                             |
|--------------------------------------------------|--------------------------------------------------------------------------------------|
| `PutAndGet_StoresAndRetrievesLexemeInfo`         | `put` stores a value and `get` retrieves it                                          |
| `Put_WithVariousLexemeInfo_StoresCorrectly`      | Parameterized over five `Type`, `Subtype`, `Use`, and `Source` combinations          |
| `Get_ForNonExistentKey_ReturnsNull`              | Missing keys return `null`                                                           |
| `Put_OverwritesExistingKey_ReturnsOldValue`      | `put` replaces the value and returns the previous one                                |
| `PutIfAbsent_Behavior`                           | Parameterized over absent key, existing key, and existing key with a different value |
| `PutIfAbsent_NullValue_StoresNull`               | A `null` value can be stored under a key                                             |
| `Size_ReturnsEntryCount`                         | `size` for empty, one-entry, and two-entry tables                                    |
| `Size_AfterPutIfAbsent_IncrementsOnlyForNewKeys` | Duplicate `putIfAbsent` calls do not increase the size                               |

Related tests:

* `src/test/java/unit/lexer/LexerSymbolTableTest.java` verifies that scanning literals populates `SymbolTable` with the expected `LexemeInfo` subtype and initial value.
* `src/test/java/unit/lexer/LexerDiagnosticHandlerTest.java` verifies the numeric, temporal, and string diagnostic classes and their fallback behavior.
* `src/test/java/integration/lexer/parser/symboltable/*IT.java` verifies parser publication for primitive, array, struct, subrange, enum, fuzzifier, defuzzifier, option, function-block interface, and declaration-error cases.
* `src/test/java/utils/ParserTestSupport.java` and `src/test/java/utils/LexemeInfoComparator.java` provide the shared parser harness and field-level comparison used by the integration tests.

Execution:

```bash
mvn test -Dtest=SymbolTableTest
mvn test -Dtest=LexerSymbolTableTest,LexerDiagnosticHandlerTest
mvn test -Dtest=PrimitiveIT,ArrayIT,StructIT,SubrangeIT,EnumerateIT
```

The POM configures Surefire but no Failsafe plugin, so `*IT` classes are not part of the default `mvn test` selection and must be named explicitly. JaCoCo writes `target/site/jacoco/jacoco.xml` during the test phase.
